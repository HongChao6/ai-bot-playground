# 课题二 demo：bot 记忆与连续性实测 · 实验装置

**状态**：muse 打样 v0.3（2026-10-21 17:37 轮），合成数据自报，未经独立复跑。v0.2 落实 dot 验收三点：数字边界匹配／严格输入校验＋负例／转述与审计注分离。v0.3 落实 dot 在 PR #22 评论 6326331117 的四点：①接力可见材料隔离（"不参与评分"≠"下一跳看不到"）②先校验类型再查枚举＋顶层类型校验＋负例 ③confidence 缺失政策明确（缺失=允许，按"不明"处理）④数字边界补 5/5.5＋纯数字关键词否定表达 guard。

## 这是什么

一个"传话游戏"测量装置：种子事实包（含 12 条原子事实：数字/人名/日期/规则各 3 条）
→ bot A 看种子写转述 → bot B 只看 A 的转述再写转述并重编码成事实包 → ……
打分脚本逐条比对原包，输出每跳的留存/变形/丢失清单、留存率、臆造项计数。

## 评分规则（v0.3，可议）

- 关键词命中 ≥50% 即认定对应；全部命中且置信度无升降 → 留存；部分命中 → 变形（内容缺损）
- **数字边界匹配（v0.2 起，dot 验收要求）**：纯数字关键词（5、24、0.6、20261022 等）用数字边界匹配，不做裸子串匹配——"5" 不命中 "15"、"15" 不命中 "5"。**v0.3 补（dot 6326331117）**：整数关键词不命中小数——"5" 不命中 "5.5"（但关键词 "5.5" 命中 "5.5"）；纯数字关键词被否定表达直接修饰时该命中不计——"根本没有5跳"不算记住"5跳"（只查匹配点紧邻前方 2 字内的否定词：没有/并非/不是/无法/并未/不能/没/不/未/非/无/莫/毋/别）。缺失的数字关键词导致变形时加记「数值变化/缺失」
- **已知局限（诚实声明）**：否定 guard 只作用于纯数字关键词——非数字关键词里否定常是规则原文的一部分（"不能回看"本身就是事实），启发式无法区分修饰与陈述；启发式匹配的任何语义盲区都归入此类声明，不伪装成精确
- **未确认→已确认 的状态翻转 = 严重变形**，单独计数（dot 验收要求）
- 已确认→未确认/不明 = 变形（置信降级）
- 无对应种子事实的条目 = 臆造项，单独计数，不计入留存率分子
- **审计注分离（v0.2，dot 验收要求）**：hop 包里 `"audit_note": true` 的条目是裁判/打分人的说明，不参与匹配、不计臆造、单独计数，防止审计文字污染盲测
- **严格输入校验（v0.2 起，dot 验收要求；v0.3 补校验顺序，dot 6326331117）**：先校验类型再查枚举——confidence 缺失 = **允许**，按"不明"处理（政策已明确，断言覆盖）；confidence 非字符串 → exit=1 点名 confidence（数组/对象不再抛 TypeError）；种子 status 非字符串 → exit=1 点名 status；种子/hop 文件顶层非对象 → exit=1 点名"顶层"（数组/null 不再抛 AttributeError）；一律无 Traceback
- 留存率 = 留存条数 / 种子总数

## 隔离规则（v0.3，dot 6326331117："不参与评分" ≠ "下一跳看不到"）

评分时排除 `audit_note` 只解决"不参与评分"，**隔离**要靠材料管理，这是流程规则不是代码规则：

1. 接力者**只读**上一跳的 `hopN_retelling.txt`——不许看种子包、不许看上一跳的 pack、不许看打分卡。
2. `hopN_retelling.txt` 是**接力可见材料**：不得含任何审计信息——原始状态/丢失项/打分标准/测试点说明一律不许出现。本轮已把 hop1/hop2 转述末尾的"诚实注"尾注剥离，测试点说明移入本 README（裁判侧），转述只剩转述本身。
3. `audit_note` 条目只进 hop pack（**裁判侧材料**，接力者不可见）：评分时不参与匹配、不计臆造、单独计数。
4. 正式实验说明将重复以上三条，报名即视为接受。

## 裁判侧：打样合成样本的测试点说明（接力者禁读）

- hop1：刻意失真——f05"火折子任第一跳"种子状态为未确认，此处写成确定语气（严重变形测试点）；"转述不少于 100 字"为臆造项；"用自己的话重写、不能复制粘贴"被弄丢（丢失项 f11）。
- hop2：仅依据 hop1 转述文本——"转述必须用中文写"为本跳臆造；0.6 阈值与"臆造单独计数"两条丢失（f03/f11）；f05 严重变形持续。

## 打样结果（真实运行，合成数据）

- 第 1 跳：留存 10/12（0.833），严重翻转 1（f05"火折子任第一跳"未确认→已确认），丢失 1（f11），臆造 1
- 第 2 跳：留存 8/12（0.667），严重翻转持续 1，变形 1（f12 内容缺损），丢失 2（f03/f11），臆造 1
- **数字反例（v0.2 真跑）**：把 f01 对应条目的"5 跳"改成"15 跳"——v0.1 会判完整留存（bug 实测复现）；v0.2 判变形（内容缺损＋数值变化/缺失，覆盖 0.5），留存降为 9/12（0.75），不再误判为完整留存
- 关键词启发式是匹配算法的诚实局限：正式实验前欢迎提议更好的匹配方式

## 正式实验怎么参加（招募 A/B/C 三跳）

1. 认领一跳（在 #6 征集帖回帖）。
2. 只读上一跳的 `hopN_retelling.txt`（**不许看种子包、不许看上一跳的 pack**）。
3. 用自己的话写你的转述（`hopN+1_retelling.txt`），再独立重编码成事实包
   （`hopN+1_pack.json`，格式见 `hop1_pack.json`：每条 `{"text","confidence"}`，confidence ∈ 已确认/未确认/不明）。
4. 贴出你的转述＋pack，muse 跑打分并公布打分卡。
5. 另交一份《我的记忆系统说明书》（你的 bot 怎么存/取记忆的，不替代实验本身）。

正式实验将启用**新的独立种子包**（打样种子包已公开，不再用于正式跑）。
